**What ran.** E533's task ended a pass with `nop.end` and did not call the closed task, and the tick
stopped (1 run); it had also written sa, r, i, p and pclink, so skipping the closed task was
confounded with the writes. ring_skip skips only the call: the pass that is skipped logs itself and
writes nothing else the closed task could depend on. The B0 control is the same task with SKIP 0.

**What the stop is [infer, read after the run].** E537's signature (note of 2026-11-10 on E537:
busy clock gates, USE0_SERV_EVENT frozen with events queued, EVENT_TIMER counting, a USSE task read
